Caught a real CSS bug before shipping, not just a visual check: `.node`'s base rule set `opacity:0` directly and relied on the `nodeIn` entrance animation's `forwards` fill to hold it visible. When `.node.lit` later reassigned the `animation` shorthand to `litPulse` (during a case trace), it fully replaced `nodeIn` -- including its forwards-held end state -- so the element fell back to the base rule's own `opacity:0` and the node visually vanished after being traced. Caught this by checking computed opacity via Playwright after firing the trace, not from a screenshot alone (a static screenshot taken before the swap would have looked fine). Fixed by moving the entrance opacity/transform/animation into a one-shot `.entering` class that JS removes on `animationend`, so the base `.node` rule has no opacity override for any later animation swap to strip away.
